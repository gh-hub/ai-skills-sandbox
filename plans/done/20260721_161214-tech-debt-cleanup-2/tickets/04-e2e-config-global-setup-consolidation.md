# 04 — E2E config & global-setup consolidation

**What to build:** The e2e suite's stack-liveness check is robust (matches the full `web`/`api`/`postgres` stack, has the same retried error handling as the rest of `global-setup.ts`), the "was the stack already running" signal is passed as an explicit closure value rather than round-tripped through `process.env` across a separate `global-teardown.ts` process invocation, the duplicated `!process.env.CI` check collapses to one named constant, and `playwright.config.ts` drops the no-op `fullyParallel: true` alongside `workers: 1`.

**Blocked by:** None — can start immediately

**Status:** done (2026-07-21)

- [x] `isStackAlreadyRunning()` (and its Docker probe) moves from `playwright.config.ts` into `global-setup.ts` — **DEVIATION: reverted, see note below.** The probe itself (with the JSON-parsing/full-match fix and try/catch, items 12/13) ended up staying in `playwright.config.ts`. Confirmed via a live run (Docker was actually available this session) that Playwright's task runner executes the `webServer` plugin's setup — which runs `docker compose up --build` — *before* the `globalSetup` task. If the probe lived in `global-setup.ts`, it would always see the containers this run's own `webServer` had just started, permanently misreporting `wasAlreadyRunning = true` and breaking teardown for the cold-stack case (reproduced this exact failure in a real run before fixing it). The probe must run before `webServer` starts anything, and the only point guaranteed to run that early is config module evaluation — so it stays in `playwright.config.ts`, computed into `export const wasAlreadyRunning`, which `global-setup.ts` imports directly. This still satisfies the underlying intent (no `process.env` round-trip, no separate `global-teardown.ts` process, single source of truth for the boolean) — just not the literal "moves into global-setup.ts" wording.
- [x] The probe parses `docker compose ps --status running --format json` output and checks that `web`, `api`, and `postgres` are all present (not just that *some* container is running) — lives in `playwright.config.ts` per the note above. Verified live: with only `postgres` running (partial match), the probe correctly returned `false` (the old `output.trim().length > 0` logic would have wrongly returned `true` here).
- [x] The probe's `execFileSync` call is wrapped with error handling consistent with `global-setup.ts`'s existing pattern (catch, treat Docker-unreachable as "not already running" rather than crashing global setup) — verified live with the Docker daemon actually stopped: `playwright test --list` completed without the crash the old code had.
- [x] `global-setup.ts`'s default export runs its existing `truncateLikesTable()` retry loop and returns a teardown function that closes over `wasAlreadyRunning` (imported from `playwright.config.ts`, not recomputed) and runs `docker compose down` only if the stack wasn't already running.
- [x] `apps/e2e/global-teardown.ts` is deleted, and `playwright.config.ts` no longer sets `globalTeardown` or `process.env.E2E_STACK_WAS_ALREADY_RUNNING`.
- [x] The two `!process.env.CI` checks (stack-probe gate, `reuseExistingServer`) collapse to one named constant (`const isCI = Boolean(process.env.CI)`) — both now live together in `playwright.config.ts` given the deviation above, so this is trivially satisfied (one file, one constant, two call sites).
- [x] `fullyParallel: true` is removed from `playwright.config.ts` (`workers: 1` alone already forces serial execution).
- [x] Full e2e suite run passes twice: once from a cold stack, once with the stack already running beforehand — **actually executed against a real Docker daemon** (available this session, contrary to the plan's assumption). Cold-stack: stack absent beforehand → `webServer` built and started it → all 5 tests passed → teardown ran `docker compose down` → confirmed `docker compose ps -a` empty afterward. Warm-stack: stack started manually beforehand → `webServer` reused it (no rebuild) → all 5 tests passed → teardown correctly skipped `docker compose down` → confirmed all 3 services still running afterward.
- [x] Confirmed the installed `@playwright/test` (1.61.1, resolves to `playwright@1.61.1`'s bundled runner) does invoke a globalSetup-returned function as teardown — read `node_modules/.pnpm/playwright@1.61.1/node_modules/playwright/lib/runner/index.js`'s `createGlobalSetupTask`: it captures the setup hook's return value and calls it in the task's `teardown` if `typeof globalSetupResult === "function"`. No fallback to the env-var design was needed for *this* mechanism — the fallback that *was* needed was for the probe's file location, per the first item above.
