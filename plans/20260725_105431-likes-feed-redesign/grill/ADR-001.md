# ADR-001: Likes API contract additions

## Status
Accepted

## Context
The API currently exposes `POST /likes` (create) and `GET /likes/count` (total count). We need to expose paginated story feed data and aggregate stats without a real materialized aggregation table.

## Decision
Add two endpoints under the existing `LikesController`:

**`GET /likes?page={n}&limit={n}`** (default `page=1`, `limit=10`)
- Filters to rows where `story IS NOT NULL AND story <> ''`.
- Orders by `createdAt DESC`.
- Returns `{ items: LikeDto[], total: number, page: number, limit: number, totalPages: number }`.

**`GET /likes/stats`**
- Computed on read from the `likes` table (no new table/column), via a single aggregate query.
- Returns:
  - `totalLikes: number`
  - `likesWithHoursReported: number`
  - `reportedHoursSaved: number` — sum of `hoursSaved` where not null
  - `percentWithoutHoursReported: number` — `(totalLikes - likesWithHoursReported) / totalLikes * 100`, `0` when `totalLikes` is `0`
  - `averageHoursPerReport: number` — `reportedHoursSaved / likesWithHoursReported`, `0` when `likesWithHoursReported` is `0`
  - `estimatedTotalHoursSaved: number` — `averageHoursPerReport * totalLikes`

## Consequences
- No schema migration needed — both endpoints are computed from the existing `likes` table.
- `shared-types` gains corresponding request/response types (`LikesPage`, `LikesStats` or similar) mirrored by new DTOs in `apps/api/src/likes/dto/`.
- Division-by-zero guarded to `0` in both `averageHoursPerReport` and `percentWithoutHoursReported` for the empty-database case.
