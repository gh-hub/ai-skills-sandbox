# Context: Admin User Management

## What we're building
An admin-only user/role management UI and API: an `/admin` hub with `/admin/users` (paginated, searchable user list with role grant/revoke) and `/admin/roles` (list/create/delete roles), gated to ADMIN only.

## Key decisions
- ADMIN-only access to all new surfaces, following the existing `RolesGuard` + `@Roles(...)` pattern; `POST /auth/signup` verified unaffected. See `grill/decisions.md`.
- `role` enum replaced by a real `roles` table with FK-based `user_roles.role_id` and a backfill migration; JWT/`AuthUser`/`RolesGuard` contracts unchanged. See `grill/ADR-001.md`.
- The `ADMIN` role can never be granted or revoked through this feature, for anyone, including an admin's own row — enforced server-side. See `grill/decisions.md`.
- Custom roles are pure labels with no enforcement wiring; only custom (non-built-in) roles are deletable, with block-by-default + force-flag deletion semantics. See `grill/decisions.md`.
- `GET /users` is paginated and searchable from the start, a deliberate deviation from this codebase's simple-list convention; response shape and default page size deferred to spec/tickets. See `grill/ADR-002.md`.

## Gotchas
- **Live e2e for tickets 04+05+06 is now closed out, not deferred.** The full suite (58 tests, all spec files) passed 58/58 as of ticket 06's session. This resolves the two-ticket deferral chain from 04/05 — no live e2e debt remains for review to pick up, though review should still re-run it once more as part of its own gate (per the skill's process), since this was implementation-time verification, not the formal review-phase gate.
- **The e2e Postgres volume persists across sessions** (`apps/e2e/global-setup.ts` only truncates `likes`), and by this session had accumulated a large amount of historical test data across many prior live runs. This directly caused one of ticket 06's session bugs (a fixed-literal admin display name in `admin-users-page.spec.ts` eventually colliding with itself across enough historical runs). Any new e2e spec should default to unique names/emails per test run, not fixed literals, to avoid the same class of failure recurring. Not fixed at the infra level (`global-setup.ts` itself) — flagged as a possible future tech-debt item, out of scope for this plan's tickets.
- **Docker was not flaky this session** — responded to `docker info` in seconds, and five separate `docker compose up --build` cycles (via Playwright's own `webServer` plugin) all completed quickly with no hangs. The flakiness reported on tickets 01/02/04/05 may not be a durable property of this sandbox; don't assume it will recur without checking first.
- **Shared roles-query cache key**: `/admin/users`'s per-user role checkboxes and `/admin/roles`'s role list both read from the exact same query key (`rolesQueryKey = ["roles","list"]` in `apps/web/lib/api-client/roles.ts`). Any future change to how roles are fetched/cached must preserve this shared key, or a role created on one page will stop appearing live on the other.
- **Hub page links use explicit `aria-label`s** (`apps/web/app/admin/page.tsx`) rather than relying on their visible child text for accessible-name computation — needed because the Users card's own description text contains the substring "roles", which made an unscoped `getByRole("link", { name: "Roles" })` match both cards. Keep this in mind if the hub page's copy changes again.
