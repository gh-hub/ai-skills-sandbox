# ADR-001: Use native IntersectionObserver for scroll-triggered UI

## Status
Accepted

## Context

This application needs to detect when a specific element (the hero card) has scrolled completely out of the viewport and show/hide UI accordingly (a sticky header). The team initially considered using an animation library (framer-motion) or an intersection-observer wrapper package (react-intersection-observer), but an audit of `apps/web/package.json` revealed neither is installed.

Adding a new dependency for this feature was explicitly ruled out as unnecessary — native `IntersectionObserver` is well-supported across all modern browsers and is sufficient for this use case.

## Decision

Use the native browser `IntersectionObserver` API via a small custom React hook to watch when the hero card element enters or leaves the viewport. Animate the sticky header's appearance with CSS transitions using Tailwind utility classes (slide + fade) rather than a JavaScript animation library.

## Consequences

**Positive:**
- No new npm dependencies — reduces bundle size and maintenance burden
- Native API is performant and built for exactly this use case
- Easy to test and debug (standard browser API)
- CSS transitions for visibility changes are lightweight and widely supported
- Establishes a pattern for future scroll-triggered UI in this codebase

**Negative:**
- Requires writing a small custom hook rather than using a pre-built solution
- IntersectionObserver config must be understood and tuned correctly (e.g., root margin) if refined later
- Browser support is modern (IE11 and earlier do not support IntersectionObserver; if legacy support is needed, a polyfill would be required)

## Alternatives considered

1. **framer-motion or similar animation library**
   - Provides more features (e.g., complex staggered animations) than needed here
   - Adds dependency overhead for a simple use case
   - Rejected due to no-new-dependencies decision

2. **react-intersection-observer package**
   - Wraps native IntersectionObserver in a convenient React hook
   - Avoids writing custom intersection logic
   - Adds a small dependency that could be avoided
   - Rejected due to no-new-dependencies decision

3. **Manual scroll-position listener (e.g., `onScroll` event handler)**
   - Simpler to understand initially
   - Less performant — fires on every pixel of scroll movement
   - More prone to jank and timing bugs
   - Rejected in favor of IntersectionObserver's event-driven, more efficient model

## Pattern for future work

When scroll-triggered UI or visibility-dependent behavior is needed elsewhere in `apps/web`, prefer native IntersectionObserver over adding dependencies. Encapsulate the pattern in a custom hook (like the one built here) and reuse it.
